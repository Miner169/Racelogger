RACE BIB LOGGER v19.2.0 — COMMAND-CENTRE OPERATIONS
====================================================

1. BACK UP AND FREEZE THE RELEASE
---------------------------------
- Copy the production Google Sheet and Apps Script project.
- Export each device's offline queue and generate a post-race/shift-handover report.
- Confirm all CommandOps records show synchronized before a Start Fresh Event.
- Retain the current production deployment until acceptance passes.
- Run: npm test
  Every stage must pass before upload.

2. GOOGLE APPS SCRIPT
---------------------
1) Replace Code.gs with the supplied v19.2.0 Code.gs.
2) Keep Fornula cell.gs only when the existing project uses it.
3) Save and deploy a new Web App version while retaining the current Web App URL where possible.
4) Open the web app once with an authorized event account so auxiliary sheets can be created/extended.

Racelog remains A:AC; no Racelog migration is required.

The backend creates or extends these auxiliary sheets without deleting existing rows:
- CommandOps: missing-runner, medical, transport/sweep, and checkpoint-supply records.
- WeatherRisk: manual weather values, thresholds, alert text, and optional provider URL.
- Incidents: acknowledgement/resolution timing, call/search counts, sighting, destination.
- DeviceHealth: connectivity and latest GPS-health fields.
- COTAlerts: resolved state, resolver, resolution time, and resolution note.

Optional weather integration:
- Manual: enter values in row 2 of WeatherRisk.
- Provider: set Apps Script Property WEATHER_PROVIDER_URL to an approved HTTPS JSON endpoint.
- Expected provider fields may include temperatureC, rainMmPerHour, windKph,
  lightningDistanceKm, observedAt, alert, and optional thresholds.
- Verify the provider's licensing, availability, privacy, and emergency-use suitability.
- Weather data is advisory; event emergency procedures remain authoritative.

4. DESKTOP / STATIC ACCEPTANCE
------------------------------
- Run npm test.
- Run node --check on app/main.js, app/director-ops-v192.js, and sw.js.
- Copy Code.gs to a temporary .js file and run node --check on that copy.
- Confirm deployment validation fails when a referenced module or icon is removed.
- Confirm every new Director widget appears in Customize and can be reordered,
  resized, hidden, restored, and scrolled at desktop and mobile widths.

5. LIVE BACKEND ACCEPTANCE
--------------------------
- CommandOps: create, edit, synchronize, reload, and resolve one record of every type.
- Event epoch: start a test event reset and confirm old CommandOps records do not re-sync.
- Arrival forecast: compare 10/20/30-minute estimates against controlled scan traffic.
- Heatmap: verify 60/120/240-minute windows and sticky checkpoint labels.
- COT funnel: acknowledge and resolve an alert; verify the resolution note persists.
- Missing runner: increment calls/searches, record a sighting, assign an owner, resolve.
- Incident timers: acknowledge, respond, resolve, reload, and verify timestamps.
- Device map: confirm battery, connection, queue, GPS age, accuracy, and last sync.
- Route anomalies: test skipped, reverse, impossible-speed, and approved-exception cases.
- Outcomes: explicitly mark DNS, DNF, withdrawn, and medical statuses.
- Finish projection: verify separate KM/category groupings and projected windows.
- Medical/transport/supplies: verify records persist offline and synchronize in a batch.
- Weather: test normal, warning, critical, stale, unavailable, and provider-error states.
- Handover: generate, copy, download, and compare against current open work.
- Post-race report: export HTML and JSON and verify timeline, incidents, COT, devices,
  checkpoint performance, weather, integrity, and reconciliation sections.

6. PHYSICAL DEVICE AND SOAK TESTS
---------------------------------
Use docs/DEVICE-TEST-MATRIX-v19.2.0.md. At minimum test:
- recent and older iPhone PWA;
- recent and low-memory Android PWA;
- tablet, landscape, large text, reduced motion;
- offline cold-open, weak/variable network, background/foreground transitions;
- real GPS, denied GPS, stale GPS, low battery, and growing offline queues;
- two-hour multi-device race traffic and command-centre refresh/load behavior.

Do not deploy to a live race based only on local automated checks.
